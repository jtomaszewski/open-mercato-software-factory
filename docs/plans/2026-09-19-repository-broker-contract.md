# Repository broker implementation contract

User-authorized real integration, local first, no fake runtime. Registry specification is `.ai/specs/2026-09-19-code-repositories.md` including the latest reconciliation.

## Shared wire contract

All broker calls use `POST /installations/verify`, `GET /installations/:id?authorizationId=...`, `GET /repositories/:githubId/branches?installationId=...&authorizationId=...`, and `POST /qualifications`. Responses are JSON, validated. Verification and grant refresh return `{ installationId: string, authorizationId: string, accountLogin: string, repositories: [{ id: string, fullName: string, defaultBranch: string }] }`; branch read returns `{ branches: string[] }`.

OAuth installation visibility is not authority over the complete App grant. Verification enumerates the user's repositories for that installation, requires write (`permissions.push`) or administrative access, and intersects that subset with the App grant. The broker persists this immutable subset under a fresh UUID `authorizationId`. OM stores it as `brokerAuthorizationId` on the scoped connection only after the connection binding commits. Every subsequent refresh, branch read and qualification requires that authorization ID to match the installation. Unknown or mismatched IDs fail closed. Refresh can shrink availability but never widen the persisted consent; reconnect creates a separate authorization record. A failed connection in another OM organization must not change an existing connection's authorization. OAuth user tokens are discarded. Authorization IDs stay in server-to-server traffic and do not appear in public UI responses or command logs.

HMAC: headers `x-om-broker-key-id`, `x-om-broker-timestamp` (Unix seconds decimal), `x-om-broker-request-id` (UUID), `x-om-broker-signature` (lowercase hex SHA256). Canonical text: uppercase method, pathname, URLSearchParams key/value lexicographically sorted and encoded by URLSearchParams, timestamp, request ID, raw body SHA256 hex, separated by newline. Never include a trailing newline. Reject duplicate query keys, invalid paths/encoding and bodies over 1 MiB. Five-minute window. Constant-time compare. Separate request and callback keys; key IDs configured for current key (rotation supports a configured map if needed). Atomic persistent replay claim before side effects. Transport errors never include remote bodies/secrets.

OM env: `REPOSITORIES_BROKER_URL`, `REPOSITORIES_BROKER_KEY_ID`, `REPOSITORIES_BROKER_REQUEST_SECRET`, `REPOSITORIES_BROKER_CALLBACK_SECRET`, `REPOSITORIES_GITHUB_APP_SLUG`, public `REPOSITORIES_GITHUB_APP_CLIENT_ID`. Explicit loopback HTTP allowed for local service; remote endpoints require HTTPS. No redirect following. OAuth install URL `https://github.com/apps/<slug>/installations/new?state=...`; existing installations use `https://github.com/login/oauth/authorize?client_id=...&state=...` with the expected installation ID stored in OM's scoped consent state. Return UI at `/backend/repositories/connect`. Broker never accepts caller callback URLs; configured OM URL only.

Broker env: `BROKER_HOST` defaults 127.0.0.1; `BROKER_PORT` defaults 5010; `BROKER_STATE_DIR` private writable persistent directory; transport key names as above; `BROKER_OM_URL`; `GITHUB_APP_ID`, `GITHUB_APP_CLIENT_ID`, `GITHUB_APP_CLIENT_SECRET`, `GITHUB_APP_PRIVATE_KEY_FILE`. Secrets stay broker-only except directional HMAC. No logs containing codes/nonces/signatures/private keys/tokens. Broker source owns its standalone package/launcher under `services/repository-broker/`; root manifests remain coordinator-owned.

Qualification request: `{ installationId, authorizationId, repositoryId, githubRepositoryId, baseBranch, epoch, attemptId, kind, profile }`. Response 202 `{ accepted: true, attemptId }`. Durable idempotent attempt keyed by attemptId. Callback signed POST `/api/repositories/internal/qualification-results`: `{ installationId, repositoryId, epoch, attemptId, status: 'passed'|'failed', report: { checks: [{ id, status: 'passed'|'failed', message }] } }`. Real checks only; unavailable isolation/toolchain/CI policy yields failed qualification, never success. Same ID with differing payload is 409. Retry callbacks with bounded persisted state; restart recovers unfinished dispatch.

## Ownership

Broker worker owns `services/repository-broker/**` only, including transport implementation and focused tests. Registry worker owns `src/modules/repositories/**` only, including app-side transport, entities, commands, routes, UI, unit tests. Coordinator owns docs, module activation, root scripts/config, migration generation and integration/runtime/browser tests. Separate transport implementations are necessary for separate service runtimes; both must obey this contract and shared protocol vectors. No worker edits Core, node_modules, existing factory/delegation code, root manifests, live secrets or Git state.
